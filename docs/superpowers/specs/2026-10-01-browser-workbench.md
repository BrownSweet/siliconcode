# Silicon Code 浏览器开发工作台

状态：个人浏览器工作台已实现，2026-10-02 通过本机真实 DeepSeek 端到端验收。范围与证据见下表。

## 产品目标

以 Codex 的项目、会话、回合、工具执行与审批交互为参照，保留现有
TypeScript/DeepSeek Agent 引擎。浏览器是主要界面，`brown serve` 启动独立服务，
无需 Ink 或伪终端。`brown code` 继续提供终端使用方式。

用户流程：登录 → 选择项目 workdir → 输入模糊需求 → 多轮澄清 → 审阅 PRD、SDD、
验收与测试/打包命令 → 开始开发 → 自动审查、测试、打包 → 查看 diff、证据与结果。
下一版本从已确认版本的需求和设计创建，保留历史文档、变更原因及回归要求，重复该流程。

## 设计约束

1. 独立浏览器服务复用 `CacheFirstLoop`、`DeepSeekClient`、`ToolRegistry`、
   文件工具、命令执行器与 `PauseGate`。不启动 Ink TUI 充当服务端。
2. 账户与模型凭据分离。默认个人管理员账户，预留用户归属字段。密码只保存带随机盐的
   scrypt 派生值；会话使用随机 HttpOnly/SameSite cookie、有效期、注销和 CSRF 校验。
   首次创建账户需要服务启动时的一次性设置凭据，不提供开放注册。
3. workdir 是运行服务所在机器的真实目录，不是浏览器上传目录。项目选择使用持久化项目 ID；
   每次请求在服务端验证归属，规范化真实路径，不允许通过路径穿越切换项目。
4. 需求版本保存原始输入、完整澄清对话、父版本、PRD、SDD、验收项、构建/测试命令及
   文档修订号。已确认快照不可原地改写；新需求通过派生新版本维护。
5. 模型可以提出澄清问题和文档草案。只有浏览器明确确认当前文档修订号后才开始开发。
   未解决问题不得被隐式当作已确认。旧版本需求和当前代码一起进入升级上下文。
6. 开发、审查和命令验证分别记录实际结果。代码修改后，旧审查、测试和打包结果失效；
   模型自报 exitCode 或 actor 不作为受信任的执行证据。
7. 每个会话有独立的运行与审批状态。并发重复启动返回冲突；刷新页面可恢复任务和审批。
   浏览器断开不会自动重复执行工具。进程重启后将未完成回合标为 interrupted，用户继续时
   先核对文件/命令结果，不自动重放可能产生副作用的操作。
8. LLM 总超时和用户取消同时有效；SSE 空闲超时独立。401/参数错误不盲目重试；
   429/临时网络错误有限退避；已经输出内容后的断流不透明重试，不把残缺输出当成功。
9. 命令有超时、停止、退出码和输出上限；工具参数错误返回可修复错误。明确区分 failed、
   interrupted、waiting_for_approval 和 completed。结束时清理进程、监听器和锁。
10. 生产部署保留单独审批边界。不能以隐藏模型工具、提示词或可填写的 actor 字段冒充
    可靠的人类身份验证。浏览器开发完成与生产发布成功分别验收。
